# DGRag application work summary

Updated October 21, 2026. Source repository: https://github.com/dougwalkerextension-sketch/DGRag.

## Sources and simulator

DGRag is a local research dashboard and labeled Poe literary simulation using three configured sources: Project Gutenberg [Volume 1, ebook 2147](https://www.gutenberg.org/cache/epub/2147/pg2147.txt), [Volume 2, ebook 2148](https://www.gutenberg.org/cache/epub/2148/pg2148.txt), and the Poe Society's [The Philosophy of Composition (1846), Text-02](https://www.eapoe.org/works/essays/philcomp.htm).

The essay frames Ask Poe's interpretations through intended effect, planning the ending, unity of impression, and deliberate choices of tone, beauty, melancholy, sound, refrain, contrast, and suggestiveness. Replies distinguish Poe's published account from invented private thoughts and distinguish interpretations of other works from explicit statements. Each conversation turn retrieves up to two essay passages and six story passages with separate Pinecone filters. The anthologies contain 30 distinct tales (8 in Volume 1 and 22 in Volume 2). Work-specific questions and follow-ups are filtered by work ID; comparisons allocate passages to every named tale. Prompts require characters, narrators, events, and quotations to remain attributed to their own works. Essay passages appear first in the numbered evidence and have inspectable links. Research mode retrieves eight passages across all sources. Missing essay evidence blocks simulator generation.

## Implementation

The Python server and responsive dashboard provide searchable source bodies, chunk inspection, pipeline events, receipts, JSON export, source citations, and follow-up conversations. Browser history retains up to 20 exchanges; the most recent six supply conversational context rather than evidence. Keyboard tabs and the direct `/#ask-poe` link are supported.

Gutenberg downloads validate ebook IDs and body markers. The essay loader validates its HTML text container, identifying text, length, and ending; it excludes navigation, scripts, styles, page labels, and external editorial notes. Raw downloads remain under ignored `data/`. The live essay produced 27,096 cleaned characters and 16 chunks. A real-source parsing check produced 684 chunks: 628 story chunks, 40 editorial chunks, and 16 essay chunks. Anthology contents entries are matched to actual body headings, including two contents spelling variants. Missing or ambiguous headings stop ingestion. Chunks use 2,100 characters with 300 overlap only within a work or editorial section and retain work title, stable work ID, parent volume, work type, author attribution, URL, work and volume offsets, capture time, and checksum. The contents, introductions, and Volume 2 endnotes remain separate editorial sections, excluded from default Ask Poe story retrieval.

Pinned MiniLM embeddings run locally on CPU with 384-dimensional normalized vectors and pooled token windows. Pinned Qwen2.5-0.5B-Instruct generates the left-hand output locally with no remote code. Ask Poe now shows three horizontal output text boxes for every prompt: current local Qwen, local Mistral 7B via Ollama, and optional OpenAI. MiniLM remains the shared retrieval embedding model; Mistral generates its own reply with an independent history. After shared evidence retrieval, model tasks run concurrently and stream independent completions. Each generative model receives its own successful reply history. A missing .env OpenAI key yields exactly not connected without a provider call; configured OpenAI uses the Responses API with store disabled and isolated errors. Research mode remains local-only. Pinecone storage uses fresh namespaces and activates only fully acknowledged ingestions. Model settings must match for retrieval. Current essay framing and evidence remain subject to the small local model's quality limits; citations should be inspected.

The three-source corpus version and indexed source URLs are recorded only on successful indexing. All earlier volume-wide indexes require reindexing to add work boundaries and metadata. The successful index also records its work catalog; preparing new documents does not replace that active catalog. Preparing texts alone preserves the active index. Partial imports support research, while Ask Poe requires an indexed essay. Previous namespaces remain available; none are deleted.
